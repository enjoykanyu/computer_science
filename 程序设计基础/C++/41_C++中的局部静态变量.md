生命周期（Lifetime）：变量在内存中实际存活多长时间（何时被创建，何时被销毁释放）。
作用域（Scope）：变量在代码的哪些位置是可见且可以被访问的


局部静态变量的本质结合
- 常规局部变量：作用域仅限于函数内部，生命周期也是局部的（离开函数就销毁）。
- 全局变量：生命周期伴随整个程序，但作用域是全局可见的（任何地方都能乱改）。
- 局部静态变量（Local Static）的独特魅力：
  它把两者的优势完美结合：生命周期等同于整个程序的运行周期（静态存储期），但它的访问作用域被严格封锁在该局部函数内部

局部静态变量拥有 静态存储期（Static Storage Duration）。在底层内存布局中，它根本不在栈上分配，而是存放在程序进程的 数据段（.data 或 .bss 内存段） 中。它的内存空间在程序加载时就已经准备好了，但真正的对象初始化会延迟到程序执行流首次经过它时触发

### 举例

```cpp
void Function() {
    int i = 0;
    i++;
    std::cout << i << std::endl;
}

int main() {
    Function(); Function(); Function(); Function(); Function();
}
```

### 把变量提到函数外部
```cpp
int i = 0; // 全局变量
void Function() {
    i++;
    std::cout << i << std::endl;
}
```
虽然能输出 1 2 3 4 5，但这极其危险：因为i是全局可见的，任何其他函数、任何人都可以随便写 i = 10;，瞬间破坏状态，造成全局状态污染

### 将变量放回函数体内，并加上 static 关键字
```cpp
void Function() {
    static int i = 0; // 局部静态变量！
    i++;
    std::cout << i << std::endl;
}

int main() {
    Function(); Function(); Function(); Function(); Function();
    // i = 10; // ❌ 编译直接报错！外界根本看不到变量 i
}
```
输出 1 2 3 4 5
首次调用 Function() 时，该变量完成初始化并被设为 0；在后续的所有调用中，它绝不会重复创建新变量，而是直接复用内存中已存在的那个i


### 底层原理
底层汇编与防重守卫标志

为什么多次调用不会重复初始化为 0？
在底层汇编中，编译器会为局部静态变量默默生成一个隐藏的守卫标志（Guard Flag，通常占 1 字节）。
伪代码逻辑如下：
```cpp
if (!guard_flag) {
    i = 0;
    guard_flag = true;
}
```

第一次调用检测到标志为 false，执行初始化并置为 true；后续所有调用直接跳过初始化指令

### 手写单例模式
```cpp
class Singleton {
private:
    static Singleton* s_Instance; // 1. 静态指针成员
public:
    static Singleton& Get() {
        return *s_Instance;
    }

    void Hello() { std::cout << "Hello!" << std::endl; }
};

// 2. 必须跑到类外部去定义并初始化这个静态指针！
Singleton* Singleton::s_Instance = nullptr;

int main() {
    Singleton::Get().Hello(); // 此时若没在某处显式 new，还会引发空指针解引用崩溃！
}
```
痛点：
- 1. 代码冗长（需要在类外额外写定义）；
- 2. 往往需要专门写一个 Init() 函数去手动 new 它，极易遗忘；
- 3. 还需要考虑何时 delete 释放，极易引发复杂内存管理
