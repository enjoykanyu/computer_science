误解：很多人以为“栈（Stack）”是存放在 CPU 高速缓存或某种特殊的高速硬件里的，而“堆（Heap）”才是物理内存。

栈和堆在物理世界上完全没有区别！它们都位于计算机同一个物理内存（RAM）芯片中

操作系统视角的内存分配：
程序启动时，操作系统加载器（OS Loader）将二进制加载进虚拟地址空间，并为其划分了不同的虚拟内存段。- 栈（Stack）：通常是一块预设固定大小的连续内存（在 Windows 上默认通常是 1 MB ~ 2 MB；Linux 默认通常是 8 MB）。
- 堆（Heap）：同样拥有初始大小，但随着程序调用 new/malloc，它可以向操作系统动态申请扩张，容量几乎只受限于物理内存和虚拟地址空间上限

### C++的标准
C++ 官方标准中并没有直接出现“栈（Stack）”这个物理词汇，而是定义为：- 自动存储期（Automatic Storage Duration）：局部对象随作用域进入而创建，退出而销毁（底层由栈实现）；
- 动态存储期（Dynamic Storage Duration）：通过 new/delete 按需申请和释放的自由存储区（Free Store / Heap）

栈溢出（Stack Overflow）的本质：
正因为栈空间非常有限（仅 1~2 MB），如果你在栈上分配超大对象（如 int arr[1000000];）或发生无限递归，栈指针一瞬间就会越过预设的保护页（Guard Page），触发操作系统的内存访问违规异常（Crash: Stack Overflow）
### 三种数据在栈与堆的分配对比

```cpp
#include <iostream>

struct Vector3 {
    float x, y, z;
    Vector3() : x(10), y(11), z(12) {}
};

int main() {
    // 1. 标量类型（int）
    int value = 5;                  // 栈分配
    int* hValue = new int;          // 堆分配
    *hValue = 5;

    // 2. 数组类型（int array）
    int array[5];                   // 栈分配
    array[0] = 1; array[1] = 2; array[2] = 3; array[3] = 4; array[4] = 5;

    int* hArray = new int[5];       // 堆分配
    hArray[0] = 1; hArray[1] = 2; hArray[2] = 3; hArray[3] = 4; hArray[4] = 5;

    // 3. 复合对象（Struct / Class）
    Vector3 vector;                 // 栈分配
    Vector3* hVector = new Vector3(); // 堆分配

    // 堆内存必须手动释放！
    delete hValue;
    delete[] hArray;
    delete hVector;
}
```


### 栈的紧密相邻对比堆的随机碎片
栈内存排布：整齐划一、紧密相邻
栈的方向（向下生长）：value 处于较高内存地址，后声明的 array 处于较低内存地址。Cherno 指出：在 x86/x64 架构下，栈是向低地址方向（反向）生长的

堆内存排布：离散分布
堆内存由操作系统的堆管理器分配，哪里的空闲块合适就塞在哪里，两者在物理地址上彼此远离、完全离散

### 分配与释放机制
栈分配与释放：纯粹的移动栈顶指针（Stack Pointer）
- 分配：
  栈顶指针（如 CPU 寄存器 ESP / RSP）往下移动对应字节数（例如分配 4 字节的 int，就将指针减 4）。
- 释放：
  当离开作用域（Scope {}）时，栈的释放是“零成本（Free）”的！
  CPU 仅执行一条加法指令把栈指针移回原来的位置，原本被占用的内存瞬间作废并准备好供下一次函数使用。不需要遍历链表，不需要任何簿记开销。

堆分配的复杂内幕：malloc、空闲链表与系统调用

当调用 new（底层的 malloc）时，系统经历了极其繁琐的幕后工作：
- 遍历空闲链表（Free List）：程序堆管理器在自己的内存池里寻找一块“大于等于请求大小”的可用连续块；
- 记录元数据（Bookkeeping / Overhead）：在分配的内存块头部额外划出空间，记录这块内存的大小、分配状态（以便将来 free/delete 时知道该释放多大空间）；
- 内存不足时的昂贵系统调用（Syscall）：如果现有堆内存池用尽，程序必须陷入内核态（向 OS 发起 VirtualAlloc 或 sbrk/mmap 系统调用），请求操作系统向物理页表申请更多物理页，开销极其沉重；
- 释放与合并（Coalescing）：delete 时还要检查相邻内存块是否空闲，执行合并碎片的操作

### 汇编
栈分配 int value = 5; 的真实汇编：
```cpp
mov  dword ptr [ebp-8], 5   ; 仅仅一条指令！直接把 5 塞进栈帧相对地址！
```
没有任何函数调用，仅需 1 条 CPU 指令，耗时不到 1 个 CPU 时钟周期

堆分配 int* hValue = new int; 的真实汇编：
```cpp
push 4                      ; 压入参数：请求 4 字节
call operator new (0xxxxxx) ; 呼叫全局 new 运算符
  ; 内部继续 call malloc
  ; 内部遍历 Free List 空闲链表...
  ; 内部加锁处理多线程竞态...
mov  dword ptr [ebp-14h], eax ; 将返回的指针存入局部变量
```
成百上千倍的开销：不仅伴随着 call 的跳转、栈帧保护，更触发了底层分配器内部海量的数据结构查找、锁竞争与元数据写入

### 栈的物理优势：Cache Friendly
- CPU 缓存行（Cache Line，通常 64 字节）：
  由于栈上的变量（如 value 和 array）在物理内存中紧密相依，CPU 读取一个数据时，会顺带把一整行 64 字节连续载入 L1/L2 高速缓存。
  - 栈数据几乎永远是热数据（Cache Hit）；
  - 离散的堆指针遍历极易造成频繁的 缓存未命中（Cache Miss），迫使 CPU 停顿数百个周期等待从主存读取
  
### 采用堆的时机
何时必须用堆（Heap）？
1. 对象生命周期必须超越当前作用域（例如需要跨函数传递所有权、被其他模块长久持有）；
2. 对象体积极其庞大（例如加载一张 50 MB 的图片纹理，强塞进栈会导致当场栈溢出）；
3. 运行期动态可变大小（如动态扩容的容器底层）

### 总结
| 维度对比 | 栈内存（Stack） | 堆内存（Heap） |
| :--- | :--- | :--- |
| **物理存储介质** | 物理内存（RAM） | 物理内存（RAM） |
| **分配与管理方式** | 编译器在底层移动栈顶指针（自动维护） | 程序员通过 `new/malloc`、智能指针向堆管理器申请 |
| **分配指令开销** | **仅 1 条 CPU 指令**（`sub esp, N`），几乎零开销 | **重型函数调用**（遍历空闲链表、簿记元数据、多线程锁） |
| **释放开销** | **零成本**（离开作用域一条指令退栈） | **较重**（调用析构函数、归还链表、合并内存碎片） |
| **生命周期** | 严格受限于声明它的局部作用域（RAII） | 由程序员显式控制，超出作用域依然存活直到 `delete` |
| **内存容量上限** | 极小且固定（通常仅 **1 MB ~ 2 MB**） | 极大，仅受限于可用虚拟内存与物理内存硬件上限 |
| **内存连续性与缓存** | **绝对连续紧凑**，极高概率命中 CPU L1/L2 缓存 | **分散随机**，频繁跨地址跳跃容易导致 Cache Miss |
| **典型越界报错** | 递归过深或分配过大 $\implies$ **Stack Overflow** | 忘记释放 $\implies$ **Memory Leak**；释放两次 $\implies$ **Double Free** |
