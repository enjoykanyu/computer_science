### 模版和范型的区别
直觉误区：很多有 Java/C# 背景的开发者常常把 C++ 模板（Templates）简单等同于“泛型（Generics）”。
本质区别：
- Java/C# 泛型：受制于类型系统与类型擦除（Type Erasure）或运行时 JIT 机制，功能极其有限，只能在预设的类型边界内工作。
- C++ 模板：功能极其庞大、近乎无所不能的编译期“高级宏（Advanced Macro / Blueprint）”！它是一套“代码生成蓝图”。

### 重复代码问题引入
```cpp
void Print(int value) {
    std::cout << value << std::endl;
}
```
打印字符串 重载print函数
```cpp
void Print(std::string value) {
    std::cout << value << std::endl;
}
```
打印浮点数
```cpp
void Print(float value) {
    std::cout << value << std::endl;
}
```
这三个函数内部除了参数类型不同，执行逻辑完全一模一样。如果哪天我们要把 std::cout 改为日志系统或 printf，就得跑到3个地方逐个重构

### 函数模板
```cpp
#include <iostream>
#include <string>

// 模板声明：typename T 也可以写成 class T
template<typename T>
void Print(T value) {
    std::cout << value << std::endl;
}

int main() {
    Print(5);           // 隐式推导为 int
    Print("Hello");     // 隐式推导为 const char*
    Print(5.5f);        // 隐式推导为 float
}
```

###  语法解剖与细节：typename vs class
- template<typename T>：告诉编译器下面是一个模板蓝图。
- T 只是一个占位标识符（Type Parameter），名字任取（可以是 Type，可以是ABC）。
- 关键字辨析：这里写 class T 和 typename T 在语义上100% 完全等价！
    - Cherno 的个人习惯：强烈偏好使用 typename。因为写 class 容易误导初学者以为只能传入类类型（如自定义 class），但事实上它完全可以接收 int、float 等基础原生类型

### 模板到底何时才真正存在

##### 显式调用对比隐式类型推导

调用模板的两种方式：
- 显式指定模板实参：Print<int>(5);Print<std::string>("Cherno");
- 隐式实参推导：Print(5);
  - 编译器根据传入的实参字面量 5，自动推导判定出 $T = \text{int}$，无需手动写尖括号
  
##### 制造语法错误
在模板内部故意拼错变量名，写了一个根本不存在的 valu：
```cpp
template<typename T>
void Print(T value) {
    std::cout << valu << std::endl; // ❌ 故意少写一个 'e'，标识符不存在！
}

int main() {
    // 关键：此时把调用代码全部注释掉，完全不调用 Print！
}
```
编译：控制台显示 0 错误，居然完美编译通过了！
一旦在 main() 里面加上一行调用 Print(5);：
编译：当场崩溃报错：error C2065: 'valu': 未声明的标识符

##### 编译通过的原因：模板实例化的本质
不调用就等于不存在：

模板本身不是实际的可执行代码，也不生成任何机器码。只有当编译器在代码中检测到你以某种具体类型（如 int）调用了该模板，编译器才会现场临时照着蓝图，把所有 T 替换为 int，完整生成（Instantiate）出一份真实的函数源码，并交给后端编译！

代码膨胀（Code Bloat）的底层逻辑：

如果你调用了 Print(5) 和 Print(5.5f)，编译器在底层实质上为你默默生成了两个完全独立的物理函数：Print_int(int) 和 Print_float(float)，分别占用不同的函数地址

### 两阶段名称查找：
为什么未使用的模板可能会跳过报错？
官方编译器在处理模板时分为两个严格阶段：
- 1. 第一阶段（模板定义期）：只检查不依赖于模板参数的纯语法错误（如缺少分号、括号不匹配）；
- 2. 第二阶段（模板实例化期）：当确定了具体的实参类型 $T$ 时，才真正解析所有依赖型名称（Dependent Names）。
   MSVC 早期历史版本对两阶段查找支持较弱，未实例化的模板检查极为宽松；而现代 Clang/GCC 会在第一阶段更严格地排查已知符号
     
### 非类型模板参数（NTTP）与手写 std::array
模板不只能接收类型，还能接收常量数值

##### 在栈上开辟编译期定长数组
传统 C++ 中，栈数组 int arr[size] 的 size 必须是一个编译期常量表达式（Compile-time Constant）。
如果写一个类封装数组：
```cpp
// 痛点：如何让大小在编译期可配置，且依然留在栈上？
class Array {
private:
    int m_Data[???]; 
};
```
##### 非类型模板参数（Non-type Template Parameters, NTTP）
```cpp
template<int N> // N 不是类型，而是一个编译期整型数值！
class Array {
private:
    int m_Array[N]; // 纯栈上数组，大小为 N！
public:
    int GetSize() const { return N; }
};

int main() {
    Array<5> array; // 编译期实例化出一个大小为 5 的专门类！
    std::cout << array.GetSize() << std::endl; // 输出 5
}
```
机制推导：Array<5> 告诉编译器：“请在编译期为我生成一个专属的类，类里面的成员变量是 int m_Array[5]”

##### 类型与大小双重模板化
把元素类型模板化，两个参数同时到位：

```cpp
template<typename T, int N> // 既有类型 T，又有数值 N
class Array {
private:
    T m_Array[N];
public:
    int GetSize() const { return N; }
};

int main() {
    Array<int, 5> intArray;
    Array<std::string, 50> stringArray; // 随心所欲定制类型与栈大小！
}
```
这属于C++标准模板库（STL）中std::array<T, N> 最底层的真正核心结构
