### 引入
语言对比：在 Python 等动态语言中，你可以极其随意地写 return a, b（底层自动打包为元组）；
但在 C++ 这种强类型静态语言中，传统函数签名在语法上只允许声明一个明确的返回类型。

真实工程背景（OpenGL 案例）：
我们需要编写一个解析着色器文本文件的函数 ParseShader(filepath)，这个函数必须同时向外吐出两个独立的字符串：
1. VertexShaderSource（顶点着色器源码）
2. FragmentShaderSource（片段着色器源码）

核心设问：如何优雅、高效且无歧义地把这两个（甚至更多不同类型的）数据带回给调用者

### 方案一：输出形参（Pass-by-Reference / Pointer 出参）
Cherno 演示的第一种思路，是完全不依赖任何复杂包装类的传统 C/C++ 方案——通过函数参数往外带数据。
1. 引用传递（Pass by Reference）出参
```cpp
void ParseShader(const std::string& filepath, std::string& vertexSource, std::string& fragmentSource) {
    // 假设内部解析得到了 vs 和 fs
    vertexSource = vs;
    fragmentSource = fs;
}

int main() {
    std::string vs, fs;
    ParseShader("res/shaders/Basic.shader", vs, fs);
    CreateShader(vs, fs);
}
```
字符串是在调用方 main 的栈帧上提前创建的，传进去的是指针地址，函数内部直接就地赋值写入那块内存。
缺点：不能写在一行中，调用前必须先声明两个空变量，代码显得略微啰嗦

### 指针出参（Pass by Pointer）与 nullptr 可选性
在很多工业库中，出参更喜欢写成指针形式：
```cpp
void ParseShader(const std::string& filepath, std::string* outVertexSource, std::string* outFragmentSource) {
    // 检查调用者是否关心该返回值（支持传 nullptr）
    if (outVertexSource)
        *outVertexSource = vs;
    if (outFragmentSource)
        *outFragmentSource = fs;
}

int main() {
    std::string vs, fs;
    ParseShader("path", &vs, &fs);        // 显式取地址 &，语义极其清晰表明是出参
    ParseShader("path", nullptr, &fs);    // 巨大优势：如果我只要 fs，vs 可以传 nullptr！
}
```
### 补充
C++ Core Guidelines 官方规范 F.20 / F.21："F.20: For 'out' output values, prefer return values to output parameters."
（对于输出值，优先使用返回值，而不是输出参数！）
核心准则委员会明确指出：出参破坏了代码从左到右的数据流向直觉，容易导致未初始化变量被误用，现代 C++ 应尽量避免将纯输出值作为形参。

### 方案二：集合容器（裸数组、std::array 与 std::vector）
如果返回的多个数据是相同类型的（如两个字符串），可以用容器打包返回。
1. 堆上裸数组指针（反例）
```cpp
std::string* ParseShader() {
    std::string* results = new std::string[2];
    results[0] = vs;
    results[1] = fs;
    return results; // ❌ 严重差评：触发堆分配，丢弃数组大小，且强迫调用方手动 delete[]！
}
```


2.  栈上定长数组：std::array
```cpp
#include <array>

std::array<std::string, 2> ParseShader() {
    std::array<std::string, 2> results;
    results[0] = vs;
    results[1] = fs;
    return results;
}
```

特点：全在栈上，无额外堆分配，且知道大小为 2

动态容器：std::vector
```cpp
#include <vector>

std::vector<std::string> ParseShader() {
    std::vector<std::string> results;
    results.reserve(2);
    results.push_back(vs);
    results.push_back(fs);
    return results;
}
```

局限：
无论是 array 还是 vector，它们都有一个致命的硬伤：只能容纳同一种类型！ 一旦未来需要返回一个 int status_code 和一个 string error_msg，容器方案立刻全线崩溃

### 方案三：标准库通用元组 std::pair 与 std::tuple
如果类型不同，C++ 标准库提供了官方泛型打包工具：
- 2 个元素：std::pair
- 任意个任意类型元素：std::tuple
1. 使用 std::tuple（元组）
```cpp
#include <tuple>
#include <utility>

std::tuple<std::string, std::string> ParseShader() {
    return std::make_pair(vs, fs); // 或者 std::make_tuple(vs, fs);
}
```
调用端提取数据时
提取麻烦
```cpp
auto sources = ParseShader();
// 提取第 0 个和第 1 个元素：
std::string vs = std::get<0>(sources);
std::string fs = std::get<1>(sources);
CreateShader(std::get<0>(sources), std::get<1>(sources));
```
2，退化到 std::pair
因为只有两个元素，改用 std::pair：
```cpp
std::pair<std::string, std::string> sources = ParseShader();
std::string vs = sources.first;
std::string fs = sources.second;
```

### C++17:结构化绑定
```cpp
// C++17 官方支持直接解构：
auto [vertexShader, fragmentShader] = ParseShader();
// 变量被赋予了有意义的名称，无需再写 std::get<0>！
```

### 方案四：自定义专用结构体 struct
1. 结构体定义与极简返回
```cpp
struct ShaderProgramSource {
    std::string VertexSource;
    std::string FragmentSource;
};

// 函数签名清晰明了：
ShaderProgramSource ParseShader(const std::string& filepath) {
    // ... 解析逻辑 ...
    // 利用 C++11 统一列表初始化（聚合初始化），极度优雅：
    return { vs, fs };
}

int main() {
    ShaderProgramSource source = ParseShader("res/shaders/Basic.shader");

    // 强烈的类型自解释性与具名成员：
    CreateShader(source.VertexSource, source.FragmentSource);
}
```
- 天然具名（Named Fields）：每一个字段都有明确的业务名称（VertexSource），绝不可能把数据张冠李戴；
- 无限扩展性：如果未来解析器还要返回着色器版本号或编译标记，直接在 struct 里面加 int Version 即可，完全不破坏现有调用；
- 性能极致（零额外负担）：本质上和 pair 一样全在栈上布局。而且配合现代编译器的 返回值优化（RVO / NRVO），返回该结构体直接在调用方的栈空间就地构造，零多余内存拷贝
