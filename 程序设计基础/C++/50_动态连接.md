### 动态链接与静态链接的根本区别
- 生命周期对比
    - 链接时机不同：
        - 静态链接（Static Linking）：发生在编译构建期（Compile/Link Time）。静态库的代码在链接阶段直接被“物理缝合”到最终生成的 .exe 内部。
        - 动态链接（Dynamic Linking）：链接发生在程序运行时（Runtime）。动态库（.dll）是一个完全独立的外部二进制文件，编译时并没有打进 .exe，而是在程序启动或执行时才被加载到进程内存空间中。
    - 性能与优化的权衡：
        静态链接时链接器拥有全局视野，能做激进的**全程序优化（LTO / LTCG）**和内联展开；动态链接因为编译期无法预知外部 DLL 的实际代码细节，调用必然伴随一层间接寻址，优化空间较小。
- 动态链接的两大流派（Cherno 的分类）
    - 1. 隐式加载 / 载入时动态链接（Load-time Dynamic Linking / "半对半"方式）：
        - 依赖配套的导入库（Import Library, .lib）。
        - 可执行文件明确将该 DLL 写入了自己的依赖清单（PE 头的导入表）。
        - 行为：双击启动 .exe 时，操作系统加载器（OS Loader）会自动检测并把相应的 .dll 一同加载进内存，如果找不到就拒绝启动并弹窗报错。本期重点！
    - 2. 显式加载 / 运行时动态链接（Run-time Dynamic Linking）：
        - 完全不需要 .lib 导入库，.exe 自身也不声明硬性依赖。
    -    行为：在代码中使用操作系统 API（Windows 的 LoadLibrary / GetProcAddress，Linux 的 dlopen / dlsym）按需动态检索路径、载入 DLL、获取函数指针调用。常用于插件系统
