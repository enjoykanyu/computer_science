### 宏定义
宏处于 C++ 编译流程的哪个阶段
源文件
→ 预处理
→ 编译
→ 汇编
→ 链接

以 # 开头的是预处理器指令：
```cpp
#include <iostream>
#define VALUE 10
#ifdef DEBUG
#endif
```
预处理阶段会先处理这些指令，再把处理后的结果交给编译器。

例如：
```cpp
#define VALUE 10
int x = VALUE;
```
预处理后近似为： int x = 10;

因此宏的本质是： 查找并替换文本
它不理解类、类型、作用域和函数语义。宏展开后，编译器才开始进行真正的语法和类型校验

### 宏与模板的区别
```cpp
#define VALUE 10       // 预处理阶段替换文本

template<typename T>  // 编译阶段处理类型和实例化
void Print(T value);
```
模板属于 C++ 语言本身，会参与类型检查；宏只是预处理器功能，所以宏可以替换的内容更加“粗暴”，甚至可以是半个表达式、花括号或完整函数

### WAIT 宏
原始代码：
```cpp
#include <iostream>

int main()
{
    std::cout << "Hello" << std::endl;
    std::cin.get();
}
```
std::cin.get() 会等待控制台输入，通常按回车后程序才继续。

定义宏
```cpp
#define WAIT std::cin.get()
```

使用它
```cpp
int main()
{
    std::cout << "Hello" << std::endl;
    WAIT;
}
```
预处理后
```cpp
int main()
{
    std::cout << "Hello" << std::endl;
    std::cin.get();
}
```


### 替换范围
宏可以替换：
- 一个数字；
- 一个表达式；
- 一条语句；
- 一部分语法；
- 一组语句

### 带参数的宏：LOG(x)
```cpp
std::cout << "Hello" << std::endl;
```

宏
```cpp
#define LOG(x) std::cout << x << std::endl
```
调用
```cpp
LOG("Hello");
```

会展开成这样
```cpp
std::cout << "Hello" << std::endl;
```
穿变量
```cpp
int value = 42;
LOG(value);
```

展开成
```cpp
std::cout << value << std::endl;
```

### 宏参数的优先级陷阱
```cpp
#define SQUARE(x) x * x
int result = SQUARE(2 + 3);
```
会展开成这样
```cpp
int result = 2 + 3 * 2 + 3;
```
由于乘法优先级更高，结果是 11，而不是 25

更安全的写法：
```cpp
template<typename T>
constexpr T Square(T value)
{
    return value * value;
}
```

```cpp
constexpr auto Square = [](auto value)
{
    return value * value;
};
```

### 宏的实际作用：Debug 与 Release
Debug 版本通常需要：
- 日志；
- 断言；
- 错误检查；
- 内存分配追踪；
- 调试辅助代码。
  Release 版本通常希望：
- 删除日志；
- 删除调试代码；
- 减少运行开销；
- 避免输出敏感信息

```cpp
#define PR_DEBUG 1
#if PR_DEBUG == 1

#define LOG(x) std::cout << x << std::endl

#else

#define LOG(x)

#endif

LOG("Hello");
```

当 PR_DEBUG == 1 时，展开为：
```cpp
std::cout << "Hello" << std::endl;
```
当 PR_DEBUG == 0 时，展开为空

此时日志代码在预处理阶段就被删除，根本不会进入编译器，也不会产生 std::cout 的运行时开销。

##### 与运行时判断的区别

```cpp
if (debug)
    std::cout << "Hello";
```

这段代码仍然会被编译，只是运行时决定是否执行。而
```cpp
#if PR_DEBUG == 1
std::cout << "Hello";
#endif
```
在 Release 构建中连这段代码都不存在。

这就是条件编译

### #ifdef 与 #if
```cpp
#ifdef PR_DEBUG

#define LOG(x) std::cout << x << std::endl

#else

#define LOG(x)

#endif
```
ifdef PR_DEBUG 即 PR_DEBUG是否被定义过

### 宏命名与命名冲突
宏没有真正的命名空间，容易和第三方库、操作系统头文件发生冲突
不建议：
```cpp
#define DEBUG
#define LOG
```
项目名前缀：
```cpp
#define PR_DEBUG 1
#define PR_RELEASE 1
#define SP_DEBUG 1
#define MYENGINE_DEBUG 1
```
比如PR可以代表项目名称，作用类似于手动建立命名空间前缀

### #if 0：禁用一整段代码
```cpp
#if 0

int value = some_invalid_code;

#endif
```
因为 0 为假，内部代码被预处理器排除。
它常用于临时禁用代码：
```cpp
#if 0
void ExperimentalFeature()
{
    // 暂时不参与编译
}
#endif
```
这也说明：即使内部代码本身存在语法错误，只要它被 #if 0 排除，编译器通常不会看到它。
长期项目中不要留下大量 #if 0，应使用版本控制、配置系统或直接删除废弃代码

### 多行宏与反斜杠

宏默认必须写在一行：
```cpp
#define MAIN int main() { std::cin.get(); }
```
换行，需要在行末使用反斜杠：
```cpp
#define MAIN            \
int main()              \
{                       \
    std::cin.get();     \
}
```
MAIN
等价于
```cpp
int main()
{
    std::cin.get();
}
```
反斜杠表示：下一行仍然属于当前宏定义。

反斜杠必须是这一行最后的有效字符：
反斜杠后有空格，可能不能正确续行

### 多语句宏的工程写法
多个语句直接写成宏可能破坏 if-else：
```cpp
#define LOG_TWO(x) std::cout << x << std::endl; \
                   std::cout << "done" << std::endl;
if (ready)
    LOG_TWO(10);
else
    std::cout << "not ready" << std::endl;                                      
```
展开后可能变成：
```cpp
if (ready)
    std::cout << 10 << std::endl;

std::cout << "done" << std::endl;

else
    std::cout << "not ready" << std::endl;
```
else就失去了对应的if

常见安全写法：
```cpp
#define LOG_TWO(x) do {              \
    std::cout << x << std::endl;     \
    std::cout << "done" << std::endl;\
} while (0)
```
这样整个宏表现为一个语句

### 宏的适用与不适用场景
适合使用宏
- Debug / Release 条件编译；
- 平台差异；
- 编译器差异；
- 日志系统；
- 断言；
- OpenGL 错误检查；
- 文件名和行号记录；
- 内存分配追踪；
- 必须在编译前剔除代码的场景。
  不适合使用宏
- 代替普通变量；
- 代替普通函数；
- 给花括号起别名；
- 给运算符起别名；
- 隐藏简单代码；
- 仅仅为了减少几次键盘输入；
- 为了炫耀语言特性。
  宏的主要问题：
1. 没有类型检查；
2. 没有正常作用域；
3. 可能重复求值；
4. 容易产生优先级错误；
5. 可能污染全局命名空间；
6. 展开后调试困难；
7. 报错位置可能不直观；
8. 宏定义可能隐藏在很远的头文件中。
